# Transaction Ledger API

Backend for a small transaction ledger. You can create accounts, add credit/debit
transactions, check balance, see transaction history and transfer money between accounts.

Built with Node.js, Express and SQLite (better-sqlite3).

## Running it

Needs Node 18 or above.

```
npm install
npm start
```

Server starts on http://localhost:3000. Use the `PORT` env variable if you want a different port.
The database file (`ledger.db`) gets created automatically in the project folder. If you change the
tables later, just delete that file and restart.

## Folder structure

```
index.js                      express app
config/db.js                  db connection, tables, constraints
routes/                       routes
controllers/                  validation + sending response
services/ledgerService.js     credit/debit/transfer logic
middleware/errorHandler.js    error handling
utils/                        AppError class and validation helpers
```

## API documentation

All endpoints with request/response examples and error cases are in [API.md](API.md).

- `POST /accounts` - create account
- `GET /accounts/:id/balance` - get balance
- `POST /accounts/:id/transactions` - add credit/debit transaction
- `GET /accounts/:id/transactions` - history (filter by type, pagination, latest first)
- `POST /transfers` - transfer between accounts (bonus)

## Assumptions

- Single currency. There is no currency field, amounts are just numbers greater than 0.
- Amounts are stored as plain decimal numbers. For a real system I would store integer minor units
  (paise/cents) to avoid floating point issues.
- No authentication, anyone who can reach the API can use it.
- Account and transaction ids are UUIDs generated by the server.
- Account names don't have to be unique.
- `reference_id` is a string. It is trimmed (so `" a "` and `"a"` are the same) and is case sensitive.
- A duplicate `reference_id` for the same account returns 409 with the existing transaction, not a
  success response. Nothing is created and the balance is not touched.
- Balance can never go below 0, there is no overdraft. Insufficient balance returns 422.
- An unknown account id returns 404 (ids are not checked for format first).
- History defaults to page 1 and 10 records per page, max 100 per page.
- Timestamps are ISO 8601 in UTC.
- Accounts can't be updated or deleted, and there is no refund/reversal API. Mistakes would be
  corrected with a new transaction.
- For transfers: same `reference_id` is used for both entries (one per account), transfers to the same
  account are not allowed, there are no fees, and if either account already used that `reference_id`
  the whole transfer is rejected.
- SQLite is used to keep setup simple. It is a single file db meant for one server instance.

## Data integrity

- Transactions can't be edited or deleted. There are no endpoints for it and there are db triggers
  that block UPDATE/DELETE on the transactions table.
- Balance update and transaction insert happen inside one db transaction, so a failed or rejected
  transaction never changes the balance.
- Constraints in the db: primary keys, unique (account_id, reference_id), foreign key on account_id,
  check on type, amount > 0 and balance >= 0.
